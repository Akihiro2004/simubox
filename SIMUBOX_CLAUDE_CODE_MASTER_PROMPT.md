## 1. PRODUCT VISION

Product: **SimuBox**
Tagline: **Ask anything. Watch it come to life.**
Core proposition: An AI-directed, isometric, interactive 3D learning world. A student asks a school-level question or uploads lesson material. Gemini Flash reasons about the best available visual teaching approach, chooses a premade world, spawns validated assets or procedural primitives, configures deterministic physics/scientific modules, choreographs an explanation using objects/characters/labels/dialogue/TTS, then lets the student interrupt, drag objects, change parameters, and ask follow-ups without losing the current scene.

SimuBox is NOT a traditional chatbot with a video thumbnail, NOT just a 3D gallery, and NOT an LLM hallucinating arbitrary Three.js code. The 3D world is the primary surface; Gemini is a **director/planner** of reliable tools implemented by us.

Core user journeys:
A) Guest opens public app -> sees beautiful interactive world immediately -> types 'What happens if gravity disappears?' -> bedroom loads, objects respond to zero gravity and an impulse, a teacher/robot explains through dialogue bubble + optional browser TTS -> user drags a ball and asks 'Now double gravity' -> existing scene changes without full reload.
B) User asks 'Launch a basketball at 40 degrees with speed 20 km/h. Where will it land?' -> court template loads -> engine converts units, calculates trajectory/range under declared assumptions (same launch/landing height, negligible drag), plays a real simulation and shows correct units/formula -> slider can adjust angle/speed -> updates without another LLM call.
C) User asks 'Why is a water molecule bent?' -> lab/scientific stage loads -> verified H2O ball-and-stick geometry appears with atom labels, bond angle annotation, rotating model, anchored explanation bubbles, interactive atom selection. Say clearly that representations are simplified educational models.
D) Authenticated user saves/reopens experiments and conversation state; guest can use a fully functional public demo without mandatory login.
E) User uploads a short PDF/text lesson, receives extracted topics and actionable suggested experiments. Unsupported topics get a structured explanation, not a fabricated scene.

## 5. PLATFORM ARCHITECTURE

Design separable layers:
1. `SimuWorld`: Three/R3F runtime, world templates, visual objects, camera, character sprites/models, markers, overlays.
2. `SimuEngine`: physics/math/molecular simulation modules and deterministic calculations; produces measurements, actions, telemetry.
3. `SimuDirector`: Gemini-driven classification/planning/teaching, tool selection, validated scene commands, lesson steps and conversational adaptation.
4. `SimuPlayer`: interruptible timeline executor syncing animations, dialogue, highlights, camera, TTS, measurement display.
5. Data layer: Firebase authentication, Firestore durable state, Cloud Storage user PDFs, analytics/error telemetry only if consent/configured.

The client owns low-latency 3D interaction; server owns authorization, Gemini orchestration, safe upload handling, session persistence and untrusted-input validation. The LLM should NOT be called on every frame or mouse move. Local interactions update deterministic engine state immediately; chat follow-ups send a compressed scene state summary + recent events.

Implement a true modular **Capability Registry**: each engine exposes supported lesson intents, template requirements, allowed parameters, actions, constraints, and evidence-based measurements. Provide a topic-to-capability matcher (simple deterministic keyword/manifest match first, Gemini chooses from short-listed capabilities). Gemini cannot claim to use arbitrary unsupported modules.

Store accepted plans and execution status. Atomic/cancellable player: steps run in order, async animations are awaitable, old timelines cancel immediately when a new request arrives, speech stops, partial state is handled, user can reset/replay and undo safe scene edits. Never let multiple concurrent plans corrupt the scene. Prefer serial command queue and monotonically increasing plan/session version.

## 7. REAL SCIENTIFIC MODULES — NONNEGOTIABLE

### MODULE A — GRAVITY / FORCES (bedroom)
- Cute furnished room with ground/walls and dynamic small objects; static furniture colliders and dynamic balls/books/boxes.
- Real Rapier rigid bodies, collision shapes, restitution, friction, actual gravity; visible change when gravity switched to zero or higher/lower values.
- Correct explanation: with gravity zero objects do not spontaneously lift from rest; they remain at rest unless another force/impulse acts. Demonstrate using a small explicit impulse or by letting user push objects.
- Users click/drag/release, manually apply impulse, toggle gravity, reset, inspect object speed/mass and compare outcomes.
- Teach gravity, inertia, net force, collisions with assumptions clearly shown. No fake motions that contradict the physics model.

### MODULE B — PROJECTILE MOTION (sports court)
- Parameter-controlled launcher and ball with speed, elevation angle and gravity. Accept degrees, m/s, km/h and convert correctly.
- Mathematical implementation and visual path agree. Under no-air-drag, flat-ground same-height assumptions use: flightTime = 2*v*sin(theta)/g, range = v*v*sin(2*theta)/g, maxHeight = v*v*sin(theta)^2/(2*g) for g>0 and v>=0; handle invalid/edge cases.
- Real animated arc, markers, landing target/range label, time/velocity breakdown where feasible, play/pause/replay.
- Interactive sliders update immediately without additional Gemini cost. Add automated numerical test cases across angles/speeds/gravity and unit conversions.

### MODULE C — ATOMS / MOLECULES (lab / science stage)
- Render true interactive ball-and-stick models with correct (curated and reviewed) connectivity, atom colors, approximate geometry, labels, zoom and rotation, select atoms and annotate bonds/angles.
- Seed verified structure data for H2O, CO2, CH4 and optionally O2/N2; source metadata, coordinates in consistent units. If using PubChem or 3Dmol.js, verify licensing/data shapes; keep offline bundled structures for reliable evaluation. A simplified atomic model (nucleus/electron-shell diagram) should be explicitly labelled schematic rather than a literal quantum-mechanical depiction.
- Gemini can choose molecule and explanation but does NOT invent bond coordinates/angles. UI picks correct renderer and verified dataset; clean fallback when molecule is unavailable.
- Use GPU instancing/simple geometry for spheres/cylinders where helpful; do not load heavyweight engines unnecessarily.

### ADDITIONAL MODE / FALLBACK
- Provide a reusable 2D/3D scientific stage for math graphs, vector arrows and diagrams if time, otherwise clean diagrams/formulas and textual interactive lesson without unsupported simulation claims.
- Subject routing should gracefully handle biology, astronomy, chemistry, math, history: classify user question, explain support level ('fully simulated', 'interactive visual explanation', 'text/diagram explanation'), never claim universal generation or actual physical precision.
